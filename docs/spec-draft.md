# Hyper-V VM モニター 仕様ドラフト

> ステータス: **レビュー反映済み（要検討事項 A〜F 確定）** / 最終更新: 2026-06-27
> 設計判断が確定しました。詳細な実装手順は `docs/implementation-plan.md` を参照。

---

## 1. 概要・目的

Windows ホスト上で動作する Hyper-V の仮想マシン（VM / ゲスト）を、Web ブラウザの
画面から一覧表示・監視し、開始／停止などの基本操作を行えるアプリケーションを作成する。

- 対象ユーザー: ホストを管理する運用者・開発者（ローカル or 同一 LAN 内での利用を想定）
- 提供形態: Blazor Server アプリ（同一ホスト上で実行し、ブラウザからアクセス）

### スコープ

| 区分 | 内容 |
|---|---|
| ✅ 本リリース対象 | VM 一覧表示、状態・CPU・メモリ・稼働時間の表示、開始／停止／一時停止／状態保存、手動更新 |
| 🔜 将来候補 | 自動更新(ポーリング/SignalR push)、リモートホスト対応、スナップショット(チェックポイント)操作、コンソール接続、認証/認可、複数ホスト集約 |
| ❌ 非対象 | VM の新規作成・削除、仮想ディスク/ネットワークの構成変更 |

## 2. 実現可能性の検証結果

開発機（本ホスト）で実機検証を行った（読み取り専用クエリのみ実施）。

| 検証項目 | 結果 | 備考 |
|---|---|---|
| Hyper-V 機能の有効性 | ✅ 有効 (`InstallState=1`) | `Win32_OptionalFeature` で確認 |
| WMI 名前空間 `root\virtualization\v2` 到達性 | ✅ 到達可 | `Msvm_ComputerSystem` が応答 |
| 参考実装が使う `Msvm_SummaryInformation` | ✅ クエリ成功 | 現状 VM 0 台のため返却 0 件 |
| Hyper-V PowerShell モジュール | ✅ 利用可 (v2.0.0.0) | `Get-VM` / `Start-VM` / `Stop-VM` 等 |
| 実行権限 | ⚠️ 非管理者 (`IsAdmin=False`) | 操作系は管理者権限実行が必要 |
| 実ゲスト VM | ⚠️ 0 台 | API 到達は確認済み。実データ検証は VM 作成後 |

**判定: 実現可能。** VM 情報の取得・状態変更とも、確立された Windows API（WMI / CIM /
Hyper-V PowerShell モジュール）で実装できる。留意点は次の 2 つ。

1. **管理者権限**: VM の状態変更（および環境によっては情報取得）には、アプリを
   管理者権限で実行する必要がある。
2. **実データ検証**: 本開発機にはゲスト VM が無いため、一覧・操作の最終確認は
   検証用 VM を 1 台用意してから行う。

## 3. 機能要件

### 3.1 VM 一覧表示
- ホスト上の全 VM を一覧表示する。
- 表示項目: 名前 / 状態 / CPU 使用率(%) / メモリ使用量(MB) / 稼働時間 / VM バージョン / (内部)GUID
- 状態はバッジ等で色分け（実行中=緑、停止=灰、一時停止/保存=黄 など）。
- 「更新」ボタンで最新状態を再取得する（初版は手動更新）。

### 3.2 VM 操作
各行のアクションボタンから以下を実行する。実行前に確認ダイアログを表示する。

| 操作 | 概要 | 実行可能な前提状態 |
|---|---|---|
| 開始 (Start) | VM を起動する | 停止 / 保存 / 一時停止 |
| シャットダウン (Shutdown) | ゲスト OS に正常終了を要求（統合サービス必須） | 実行中 |
| 強制停止 (Turn Off) | 電源を即時オフ（データ損失リスクあり、要強調確認） | 実行中 / 一時停止 |
| 一時停止 (Pause) | 一時停止する | 実行中 |
| 再開 (Resume) | 一時停止から復帰 | 一時停止 |
| 状態保存 (Save) | メモリ状態を保存して停止 | 実行中 |

> 「停止」には **正常シャットダウン**（ゲストに依頼）と **強制電源オフ**（即断）の
> 2 系統がある。初版でどこまで出すかは「要検討事項 C」を参照。

### 3.3 操作のフィードバック
- 操作中はボタンを無効化し、進行中インジケータ（オーバーレイ/プログレス）を表示。
- 完了/失敗をトースト通知し、失敗時はエラーメッセージを画面に表示。
- 操作完了後に一覧を自動で再取得する。
- 状態遷移は非同期で完了まで待機（成功/タイムアウトを判定）。

### 3.4 状態と操作の整合
- 現在の状態で実行不可能な操作のボタンは無効化/非表示にする
  （例: 実行中の VM に「開始」は出さない）。

## 4. 非機能要件

| 区分 | 要件 |
|---|---|
| 動作環境 | Windows 10/11 または Windows Server、Hyper-V 役割が有効なホスト |
| ランタイム | .NET 10 / C# (Directory.Build.props に準拠) |
| 権限 | 管理者権限での実行を前提（起動時に権限不足を検知し明示） |
| 性能 | VM 数十台規模で一覧取得が体感数秒以内 |
| 品質 | ビルド警告ゼロ（StyleCop / CA / Nullable をエラー扱い）。コードコメントは英語（JapaneseComment アナライザー対応） |
| セキュリティ | 初版はローカル利用前提。外部公開時は認証・HTTPS 必須（将来課題） |
| 可用性 | 単一プロセス。VM 操作の失敗がアプリ全体を落とさないこと |

## 5. アーキテクチャ / 技術スタック

参考にした `CloudManager`（Blazor Server + MudBlazor + Usecase 層）の構成を踏襲する。

```
ブラウザ
   │  (Blazor Server / SignalR)
┌──┴───────────────────────────┐
│  Web (Blazor Server, MudBlazor)              │  ← 画面・操作・通知
│   ├─ Components/Pages   (VM 一覧ページ)       │
│   ├─ Components/Shared  (確認ダイアログ等)    │
│   └─ Services           (Toast 等 UI 補助)    │
└──┬───────────────────────────┘
   │  (Usecase 呼び出し)
┌──┴───────────────────────────┐
│  Core (Hyper-V アクセスライブラリ)            │  ← VM 取得・操作の実体
│   ├─ HyperVUsecase   (一覧/開始/停止…)        │
│   ├─ Models          (VmInfo, VmState…)       │
│   └─ HyperVClient    (WMI/CIM/PS のラッパー)  │
└───────────────────────────────┘
            │
   Hyper-V (root\virtualization\v2 / Hyper-V PS module)
```

### 確定している採用技術
- **Blazor Server**（`AddInteractiveServerComponents`）
- **MudBlazor**（一覧 `MudTable`、`MudDialog`、`MudSnackbar`、状態バッジ `MudChip`）
- **.NET 10**、`Nullable enable`、`ImplicitUsings enable`
- コードビハインド方式（`.razor` + `.razor.cs`）、`record` 型で DTO 定義
- メンバ変数は `_` プレフィックス無し（AGENTS.md / 既存設定に準拠）

### 参考実装からの再利用
- `CloudManager` の `RunOperationAsync` / `ConfirmAsync` / `ToastService` /
  `ProgressOverlay` / `ConfirmDialog` パターンをほぼそのまま流用可能。
- `PrometheusExporter.Instrumentation.HyperV` の `Msvm_SummaryInformation` 取得ロジック
  （`EnabledState==2` で実行中判定、CPU/メモリ/Uptime 抽出）を一覧取得に流用可能。

## 6. Hyper-V アクセス方式の比較（要決定）

VM の取得・操作をどの API で実装するか。3 案を比較する。

| 観点 | A. WMI (System.Management) | B. CIM (Microsoft.Management.Infrastructure) | C. Hyper-V PowerShell モジュール |
|---|---|---|---|
| 参考実装との一貫性 | ◎ 同一（流用最大） | ○ 近い | △ 別方式 |
| 取得の実装容易性 | ○ | ○ | ◎ (`Get-VM`) |
| 操作の実装容易性 | △ `InvokeMethod`+ジョブ待ち | △ 同様 | ◎ (`Start/Stop/Suspend/Save-VM`) |
| 状態遷移待ちの容易さ | △ `Msvm_ConcreteJob` 監視が必要 | △ 同様 | ◎ コマンドが完了まで待つ |
| 外部依存 | DLL 参照のみ | DLL 参照のみ | Hyper-V PS モジュール必須(確認済) |
| 実行時オーバーヘッド | ◎ 低 | ◎ 低 | △ PS 実行コスト |
| 対象 TFM | `net10.0-windows` | `net10.0-windows` | `net10.0-windows` |

> **推奨（たたき台）**: **取得は A(WMI)** で参考実装を流用、**操作も A(WMI)** に統一し
> 外部依存を増やさない案を基本線とする。ただし操作の堅牢性・実装速度を優先するなら
> **操作のみ C(PowerShell)** を併用するハイブリッドも有力。最終決定は「要検討事項 A」。

### 参考: WMI での状態値と操作（実装時に Microsoft Learn で要確定）
- `EnabledState`: `2`=実行中, `3`=停止(オフ)、その他=一時停止/保存/遷移中など。
- 操作は `Msvm_ComputerSystem.RequestStateChange(RequestedState)`:
  `2`=起動, `3`=強制オフ ほか（保存/一時停止の値は実装時に確認）。
- 正常シャットダウンは `Msvm_ShutdownComponent.InitiateShutdown`（統合サービス必須）。
- 長時間操作は `Msvm_ConcreteJob` を監視して完了/失敗を判定する。

## 8. プロジェクト構成案（要決定）

ソリューション名は既存の `Monitor.slnx` を踏襲。

**案1: 2 プロジェクト分割（推奨・CloudManager 流）**
```
Monitor.slnx
├─ src/Monitor.Web/    … Blazor Server (UI)         net10.0-windows
└─ src/Monitor.Core/   … Hyper-V アクセス/Usecase    net10.0-windows
```
- 関心分離・テスト容易。将来 CLI 等から Core を再利用可能。

**案2: 単一プロジェクト**
```
Monitor.slnx
└─ src/Monitor.Web/    … UI + Hyper-V アクセス        net10.0-windows
```
- 小規模なら最短。後から分割も可能。

> どちらも `net10.0-windows`（WMI / Hyper-V API は Windows 専用のため）。
> 最終決定は「要検討事項 B」。

## 9. 権限・セキュリティ

- **管理者権限**: 操作系 API は昇格が前提。`app.manifest` で
  `requireAdministrator` を指定する案／起動時に権限を検知して警告表示する案。
  → 開発時の利便性を考え、初版は「起動時検知＋警告」、配布時に manifest 検討。
- **公開範囲**: 初版は `localhost` バインドを基本とし、LAN 公開・認証は将来課題。
- **監査**: 誰がどの VM をいつ操作したかのログ（初版はアプリログのみ）。

## 10. 決定事項（レビュー反映済み）

2026-06-27 のレビューで以下を確定した。

| ID | 論点 | 決定 | 備考 |
|---|---|---|---|
| **A** | Hyper-V アクセス方式 | **CIM に統一**（`Microsoft.Management.Infrastructure`） | 取得・操作とも CIM。検証時の `Get-CimInstance`(=CIM/MI 基盤) で到達を実証済み |
| **B** | プロジェクト構成 | **2 分割**（`Monitor.Web` + `Monitor.Core`） | 関心分離・将来の再利用性 |
| **C** | 「停止」操作の既定 | **両方提供**（正常シャットダウン＋強制電源オフ） | 強制側は警告を強化した確認ダイアログ |
| **D** | 自動更新 | **初版は手動更新** | 将来ポーリング/push を検討 |
| **E** | 管理者権限の与え方 | **起動時に検知して警告** | manifest 強制は配布時に再検討 |
| **F** | プロジェクト/名前空間名 | **`Monitor.Web` / `Monitor.Core`** | ソリューションは既存 `Monitor.slnx` |

> アクセス方式が **CIM** に確定したため、本書 5〜6 章中の「WMI 推奨」表現より本章を優先する。
> 取得対象クラス（`Msvm_SummaryInformation` 等）や状態値は CIM でも同一名前空間・同一クラスを用いる。

## 11. 想定リスク

| リスク | 対応 |
|---|---|
| 開発機に実 VM が無く実データ検証不可 | 検証用 VM を 1 台用意。それまではホスト ComputerSystem 等でスモーク確認 |
| 管理者権限不足で操作失敗 | 起動時に権限検知し UI 明示。操作失敗を握りつぶさずトースト表示 |
| 長時間ジョブ（起動/保存）でのタイムアウト | 状態ポーリング＋タイムアウト値を設定可能に |
| WMI 操作系コードの煩雑さ | 必要に応じ操作のみ PowerShell へ切替（案 C） |
| Blazor Server の接続断 | 操作は冪等性を意識。再接続後に一覧再取得 |
